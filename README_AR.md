# ALBYATE FOR SOLAR INVERTER — النسخة التجريبية 0.3.2

هذا مشروع مصدر Flutter للنسخة الأولية من نظام إدارة مركز صيانة الإنفيرترات.

## الموجود في هذه النسخة
- تسجيل مركز محلي وإنشاء حساب مالك دون OTP.
- تسجيل دخول محلي بكلمة مرور مخزنة على شكل SHA-256.
- واجهة عربية وإنجليزية مع تغيير اتجاه الواجهة.
- لوحة تحكم وإحصائيات أولية.
- تسجيل الأجهزة والبحث بالسيريال/الموديل/اسم الزبون.
- قراءة الباركود بالكاميرا (1D/QR حسب دعم المكتبة والجهاز).
- تصوير ملصق الجهاز، حفظ الصورة، ومحاولة استخراج الأرقام من الصورة باستخدام OCR.
- سجل إصلاح أولي وربط دفعة الصيانة بالحسابات.
- إدارة قطع الغيار والكميات وأسعار الشراء والبيع.
- سجل زبائن مع رقم الهاتف والعنوان وفئة التسعير وحد ائتماني.
- كشف حساب لكل زبون وتسجيل الدفعات المستلمة.
- فواتير سحب مواد متعددة الأصناف مع خصم المخزون تلقائياً وتسجيل حركة المخزن.
- تسجيل المبالغ المدفوعة والمتبقية على فاتورة الزبون، مع منع تجاوز حد الدين الائتماني المحدد.
- تسجيل الإيرادات والمصروفات.
- إضافة موظفين محلياً بأدوار: فني، حسابات، أمين مخزن، ومالك.
- قاعدة بيانات SQLite محلية تعمل دون إنترنت.

## ملاحظات مهمة قبل اعتبارها نسخة إنتاجية
1. **هذه حزمة مصدر أولية وليست APK جاهزاً.** بيئة البناء المتاحة أثناء إعدادها لا تحتوي Flutter SDK أو Android SDK، لذلك لم يتم تجميع APK أو اختباره على هاتف فعلي.
2. المزامنة بين أجهزة المركز نفسه وفصل بيانات المراكز على خادم متعدد المستأجرين لم يُنفّذا بعد. الواجهة والحقول المحلية تمهيد للمرحلة التالية؛ لا تستخدم هذه النسخة لتبادل بيانات حقيقية بين الهواتف.
3. صلاحيات الأدوار معروضة كبداية، وتحتاج إلى فرض كامل على مستوى كل عملية وشاشة قبل الإنتاج.
4. OCR اقتراح آلي وقد يقرأ رقم الموديل بدلاً من السيريال أحياناً؛ يجب اختبار صور ملصقات فعلية متعددة وتأكيد النتيجة قبل حفظها. الباركود هو المسار المفضل عندما يحتوي السيريال.
5. النسخة لا تخصم قطع الغيار تلقائياً من المخزون عند الإصلاح بعد؛ يلزم بناء ربط استهلاك القطع وفواتير الشراء/البيع في المرحلة التالية.
6. يلزم إضافة نسخ احتياطي واستعادة مشفرين، وتشفير أسرار الدخول، وسياسة استعادة كلمة المرور، واختبارات أمنية قبل النشر.

## إنشاء ملفات Android وتجميع APK
يتطلب ذلك تثبيت Flutter SDK وAndroid Studio/Android SDK على جهاز بناء.

من داخل مجلد المشروع:

```bash
flutter create . --platforms=android
flutter pub get
flutter run
flutter build apk --release
```

سيظهر ملف APK عادة في:
`build/app/outputs/flutter-apk/app-release.apk`

## ALBYATE AI — تكامل المحادثة عبر الإنترنت (مرحلة أولى)

- أضيفت شاشة محادثة باسم ALBYATE AI من زر النجمة في الشريط العلوي.
- تستخدم Firebase AI Logic مع Gemini Developer API عبر حزمة `firebase_ai`.
- نموذج المحادثة مضبوط حالياً على `gemini-3.8-flash` وفق وثائق Firebase الحالية.
- المحادثة متعددة الأدوار وتدعم بث الردود أثناء توليدها.
- لا ترسل هذه المرحلة بيانات الزبائن أو الحسابات أو المخزن إلى النموذج؛ المساعد يقدم مساعدة فنية عامة فقط.
- إذا لم ينجح إعداد Firebase، تبقى وظائف التطبيق المحلية متاحة وتظهر رسالة توضح أن المساعد غير مهيأ.

### إعداد Firebase المطلوب
1. تأكد من أن تطبيق Android مسجل في مشروع Firebase بالمعرّف `com.albyate.solarinverter`.
2. تأكد من أن Firebase AI Logic مفعّل وأن مزود Gemini Developer API جاهز في وحدة تحكم Firebase.
3. إعداد App Check لتطبيق Android. يستخدم إصدار debug مزود App Check debug، ويستخدم إصدار release مزود Play Integrity. يجب تسجيل التطبيق وإعداد بصمة التوقيع/توزيع التطبيق في Firebase App Check قبل الاعتماد على AI في إصدار release.
4. حصة Gemini Developer API المجانية محدودة وليست استخداماً غير محدود؛ قد تتغير الحصص والتوفر حسب المنطقة والسياسة.
5. لا تضع مفتاح Gemini API مباشر داخل التطبيق. Firebase AI Logic يمرر الطلبات عبر خدمة Firebase الوسيطة.

### ملاحظة الخصوصية
لا يقرأ ALBYATE AI في هذه المرحلة سجلات الزبائن أو تفاصيل الحسابات أو بيانات المخزن. ربطه بهذه البيانات سيكون مرحلة منفصلة، مع صلاحيات واضحة وموافقة صاحب المركز، وإرسال أقل قدر ممكن من البيانات.
